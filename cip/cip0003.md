# CIP-0003: Publication Template Rendering and CiteProc Validation

## Status

- [x] Proposed - Initial idea documented
- [ ] Accepted - Approved, ready to start work
- [ ] In Progress - Actively being implemented
- [ ] Implemented - Work complete, awaiting verification
- [ ] Closed - Verified and complete
- [ ] Rejected - Will not be implemented
- [ ] Deferred - Postponed

## Summary

Define how we prove Fenner templates **render correctly** and stay aligned with
the bibliographic field model across layout types and both path-1/path-2
encodings. This CIP covers test fixtures, build smoke tests, HTML assertions,
and CiteProc/export consistency — not the survey (CIP-0001) or installer
(CIP-0002).

**Requirements addressed**: REQ-0002, REQ-0003, REQ-0004

## Motivation

REQ-0003 demands one publication record across HTML cite UI, SEO metas, and
copy/export formats. REQ-0004 demands path-1 and path-2 themes share one core.
Without automated checks, reinstall into eleven forks will regress silently.

Validation-led development: encode acceptance criteria as tests **before** or
alongside extraction, not after manual spot-checks.

## Detailed Description

### Test layers

```
┌─────────────────────────────────────────────────────────┐
│ Layer 4: Pilot theme builds (optional CI, manual first) │
│   jekyll build on mlatcl + mlresearch fixtures          │
├─────────────────────────────────────────────────────────┤
│ Layer 3: Export / field consistency                     │
│   citeproc.yaml, copy_sections output vs extract        │
├─────────────────────────────────────────────────────────┤
│ Layer 2: Rendered HTML smoke                            │
│   jekyll build on Fenner fixture site → grep assertions   │
├─────────────────────────────────────────────────────────┤
│ Layer 1: Static / unit (fast)                           │
│   Liquid render with fixture posts; include presence    │
└─────────────────────────────────────────────────────────┘
```

### Fixture design

**Fenner fixture site** under `test/fixtures/site/` (or `spec/fixtures/`):

Minimal Jekyll site using Fenner layouts/includes directly (not full org theme
chrome). Contains golden posts:

| Fixture post | Layout | Purpose |
|--------------|--------|---------|
| `article-csl.md` | `article` | Full CSL-shaped front matter (`issued`, `container-title`, DOI, authors) |
| `inproceedings-minimal.md` | `inproceedings` | Minimal required fields |
| `techreport-legacy.md` | `techreport` | Legacy alias keys (survey from CIP-0001) |
| `report-delve.md` | `report` | `cite-as` / DELVE-style report fields |
| `article-path2.md` | `article` via path-2 wiring | Same fields, `paper_abstract` body path |

Front matter exemplars come from CIP-0001 `content-contract-samples.md`.

**Theme integration fixtures** (lighter weight):

- Submodule or script-cloned **theme stub** that wraps Fenner with minimal
  `default.html` — tests REQ-0001 separability without full org chrome.

### Layer 1 — Static checks (no Jekyll)

- Manifest test: every path in `fenner-owned-paths.txt` exists in Fenner repo.
- Include graph: required includes referenced by layouts resolve.
- Optional: golden-file tests for `extractinfo_publication` output given fixture
  YAML (Ruby/Liquid test helper or small Jekyll tag test).

### Layer 2 — Jekyll build smoke

Run the Fenner-owned fixture site (no sibling theme/volume required):

```bash
./scripts/pilot_build_fixture.sh         # path-1 wiring
./scripts/pilot_build_fixture.sh --path2 # path-2 wiring
```

Fixture root: `test/fixtures/site/` — minimal chrome + golden posts; Fenner
manifest paths are staged in at build time.

**HTML assertions** (via `grep` in the pilot script; later Nokogiri/Ruby):

- [x] Page title and h1 match fixture `title`
- [x] Author names appear in body
- [x] Venue/container line present for proceedings
- [x] “Cite this Paper” or equivalent section present
- [x] `citation_title` meta (Google Scholar) matches title
- [x] DOI link present when fixture has DOI
- [x] No Liquid error output in build log
- [x] `assets/bib/citeproc.yaml` contains fixture title

**Layout contract tests** (REQ-0002):

- Each type layout builds without error.
- Renaming test: fixture keeps `layout: article` — no Fenner-internal rename.

### Layer 3 — CiteProc / export consistency (REQ-0003)

For each golden post after build:

1. **On-page vs meta**: author list and year in body match
   `meta[name=citation_*]` where applicable.
2. **Copy sections**: rendered BibTeX / APA blocks contain fixture DOI or
   container-title when provided (string grep on built HTML hidden copy areas
   or JavaScript data attributes if used).
3. **`citeproc.yaml` output**: build site, fetch `/assets/bib/citeproc.yaml`
   (or generated path), parse YAML, assert fixture post appears with matching
   `title`, `author`, `issued`, `DOI`.

Path-1 vs path-2: **same assertions** on both wiring fixtures (REQ-0004).

### Layer 4 — Installed-theme pilot builds

After CIP-0002 install into pilot themes:

- `jekyll build` on a **minimal content slice** (1–2 posts) checked into test
  harness or copied from real repos.
- Compare key HTML fragments before/after install (optional diff baseline from
  pre-Fenner theme — survey may capture).

**Path-2 (PMLR) smoke script** (manual Layer 4 checklist item):

```bash
./scripts/pilot_build_v16.sh
# optional overrides:
THEME=~/mlresearch/jekyll-theme SITE=~/mlresearch/v16 DEST=/tmp/v16-out \
  ./scripts/pilot_build_v16.sh
```

Symlinks the local theme into `v16`, builds without the volume `Gemfile`
(`github-pages` bundle optional), asserts “Cite this Paper” on a sample paper
and `class="paper"` volume listings. Theme SCSS with Liquid `@import` is
excluded under Jekyll 4.4 + dart-sass; HTML/citation rendering is the pilot
target. For production-parity CSS, use the volume’s own
`bundle install && bundle exec jekyll build`.

Not all eleven themes in CI initially — matrix expands as installs roll out.

### CI strategy

**Phase 1** (Fenner repo only):

```bash
bats scripts/test/*.bats
./scripts/pilot_build_fixture.sh
./scripts/pilot_build_fixture.sh --path2
```

**Phase 2**: GitHub Actions (`.github/workflows/ci.yml`) on push/PR —
install bats + Jekyll, run install tests and both fixture builds.

**Phase 3**: Scheduled workflow re-runs survey matrix diff (CIP-0001 script)
against consumer themes — drift alarm, not blocking initially.

### Tooling choices

| Tool | Role |
|------|------|
| **bats** | Install script, shell orchestration |
| **Jekyll** | Fixture site build |
| **Ruby script** | HTML/meta/export assertions (keeps logic out of bats) |
| **PyYAML** | Parse `citeproc.yaml` in assertions (`.venv-vibesafe` ok for dev) |

Avoid full browser/system tests for v1 — static HTML is enough.

### Failure taxonomy

| Failure | Likely cause |
|---------|----------------|
| Liquid error on build | Missing include after extract |
| Meta mismatch | SEO include not using extract pass |
| Copy block missing DOI | `*_entry` template drift |
| Path-2 only failure | Adapter not wired in type layout |
| Install test failure | Manifest overwrote wrong path |

## Implementation Plan

1. **Define fixture posts** from CIP-0001 content samples.
2. **Create `test/fixtures/site/`** with `_config.yml`, Gemfile, minimal
   chrome layouts, Fenner layouts staged at build time.
3. **Implement `scripts/pilot_build_fixture.sh`** with HTML/citeproc smoke
   assertions (path-1 and `--path2`).
4. **Wire CI** via `.github/workflows/ci.yml`.
5. **Wire CIP-0002 install tests** into same CI job.
6. **Document** running tests in README.
7. **Optional:** `scripts/pilot_build_v16.sh` for live PMLR volume smoke;
   path-1 mlatcl pilot remains a manual checklist.

## Backward Compatibility

Tests encode **current** layout names and include contracts. Changing public
contracts requires updating fixtures and a migration CIP — tests guard
REQ-0002.

## Testing Strategy

Meta — this CIP defines the strategy. Done when:

- [ ] Fixture site builds green locally
- [ ] Assertions fail when extract pass is deliberately broken (sanity check)
- [ ] Path-1 and path-2 fixtures both pass same Layer 3 checks
- [ ] Install idempotency tests pass (CIP-0002)
- [ ] README documents test commands
