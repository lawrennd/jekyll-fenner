# CIP-0002: Idempotent Fenner Install Into Organisation Themes

## Summary

Design and implement `script/install` so Fenner-owned templates can be copied
(or symlinked where appropriate) into organisation `jekyll-theme` checkouts
**safely and repeatedly**. Install must implement REQ-0005 without violating
REQ-0001 (chrome stays theme-local).

**Blocked on**: CIP-0001 `fenner-owned-paths.txt` manifest — install scope is
not guesswork.

**Requirements addressed**: REQ-0001, REQ-0005

## Motivation

Hand-merging thirty files across eleven forks is why Fenner exists. An install
script that is not idempotent would recreate the same failure mode: fear of
re-running, stale partial copies, accidental overwrites of `header.html`.

REQ-0005 states the outcome; this CIP defines the mechanism.

## Detailed Description

### Install modes (design options)

| Mode | Pros | Cons | When |
|------|------|------|------|
| **Copy** | Works with GitHub Pages `remote_theme`; no gem dependency | Drift until reinstall | Default v1 |
| **Symlink** | Live dev against Fenner checkout | Breaks CI/Pages unless path fixed | Local dev only (`--symlink`) |
| **Ruby gem** | Bundler-managed | Pages remote_theme consumers still need vendoring | Later CIP if needed |

**Recommendation**: Ship **copy install** first; optional `--symlink` for
local theme development.

### Install contract

```
FENNER_ROOT=~/lawrennd/jekyll-fenner ./script/install /path/to/jekyll-theme
```

**Inputs**:

- `FENNER_ROOT` — Fenner checkout (default: parent of `script/install`)
- Target theme directory (required argument)

**Behaviour**:

1. Read `fenner-owned-paths.txt` (from CIP-0001) — authoritative manifest.
2. For each path:
   - If Fenner source exists: copy file to theme (create parent dirs).
   - If Fenner source removed in new release: optionally `--prune` removes
     stale Fenner-owned files (off by default until v2).
3. **Never touch** paths not in manifest (headers, footers, `_includes/pmlr/`,
   etc.).
4. Write audit stamp, e.g. `.fenner-installed` JSON:

   ```json
   {
     "fenner_commit": "abc123",
     "installed_at": "2026-09-01T12:00:00Z",
     "manifest_version": "1",
     "paths_installed": 42
   }
   ```

5. Exit non-zero if target is not a git repo or missing `_config.yml` (sanity
   check — warn-only flag to override).

### Conflict policy

| Situation | Policy |
|-----------|--------|
| Theme file not in manifest | **Skip** (org-owned) |
| Manifest path, theme file absent | **Create** |
| Manifest path, identical content | **No-op** (idempotent) |
| Manifest path, differs from Fenner | **Overwrite** (Fenner wins) unless `--dry-run` |
| Theme patched Fenner-owned file | **Overwrite** on reinstall — genuine org behaviour must live outside manifest or use documented override hook |

Override hook (future): ` _fenner_overrides/` or theme-local wrapper includes
— not v1 unless survey finds widespread patches (CIP-0001).

### Path-2 theme install notes

Path-2 themes may need **one theme-local line change** after install (e.g.
`article.html` parent layout) depending on CIP-0001 adapter decision. Install
script installs Fenner files only; document post-install steps in installer
output and README.

### Distribution packaging

Initial deliverable lives in `jekyll-fenner/script/install` (bash, bats-tested).
Optional later: `jekyll-fenner.gemspec` with `spec.files` limited to Fenner
paths — out of v1 scope unless Pages gem path is required.

### Security / safety

- Refuse to install if target is Fenner repo itself (avoid recursion).
- Refuse `/` or `$HOME` as target without `--force`.
- `--dry-run` lists would-copy / would-overwrite without writing.

## Implementation Plan

1. **Wait for CIP-0001 manifest** — `fenner-owned-paths.txt` checked into Fenner
   root or `script/`.

2. **Implement `script/install`**
   - Parse manifest (comments and blank lines allowed).
   - Copy with `install(1)` or rsync `--files-from`.
   - Write `.fenner-installed` stamp.

3. **Flags**
   - `--dry-run`, `--symlink`, `--force`, `--verbose`

4. **Document in README**
   - Install one-liner, re-install upgrade path, audit stamp location.

5. **Pilot installs** (manual, pre-automation)
   - One path-1 theme (`mlatcl/jekyll-theme`)
   - One path-2 theme (`mlresearch/jekyll-theme` from fresh clone)
   - Verify chrome files untouched (CIP-0003 checks).

6. **Bats tests** in `scripts/test/install-test.bats` (or Fenner-local equivalent).

## Backward Compatibility

- First install adds files; does not remove theme-local chrome.
- Re-install overwrites only manifest paths — predictable for maintainers.
- Themes with pre-Fenner private copies of cite includes will see overwrites;
  survey (CIP-0001) should flag DIFFERS cells before first pilot.
