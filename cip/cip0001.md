## Summary

Before copying anything into `jekyll-fenner`, we need a evidence-based inventory of
what the public consumer themes actually ship today — including how those files
evolved in git history — and a decision on the **canonical Fenner-owned set**
that satisfies REQ-0001 through REQ-0004 without breaking REQ-0002 layout
contracts.

This CIP is the design phase: survey, compare, decide. Extraction and install
belong in CIP-0002; validation belongs in CIP-0003.

**Requirements addressed**: REQ-0001, REQ-0002, REQ-0003, REQ-0004, REQ-0006

## Motivation

The README already lists eleven public themes in two rendering paths (path-1:
`publication` + `paper_authors_abstract_links`; path-2: `default` +
`paper_abstract`). Local checkouts may be stale (e.g. `mlresearch`, empty
`rs-delve`). Hand-waving “extract from lawrennd” risks baking in accidental
divergence or missing the latest encoding on GitHub.

We need a **survey artefact** — not just a file list — that answers:

1. Which layouts/includes are shared, forked, or theme-local chrome?
2. When did path-1 vs path-2 split, and which themes never caught up?
3. What is the smallest common set that still renders all live layout types?
4. How do legacy aliases map to the bibliographic model (REQ-0003)?

Without this, install and test work would guess at scope.

## Detailed Description

### Survey scope

**In scope for inventory** (Fenner candidate paths):

| Category | Examples |
|----------|----------|
| Type layouts | `article`, `inproceedings`, `techreport`, `report`, `addendum`, … |
| Publication shell | `publication.html` (behaviour only; chrome may stay theme-local) |
| Body includes | `paper_authors_abstract_links`, `paper_abstract`, `listpaper`, `listauthors` |
| Field extract | `extractinfo_publication`, `extractname`, … |
| Cite / export | `cite-as`, `copy_sections`, `*_copy_section`, `*_entry` |
| SEO / discovery | `seo-info`, `paper_google_scholar`, `paper_open_graph_meta`, `paper_twitter_meta` |
| Bibliography export | `assets/bib/citeproc.yaml` |
| Report-style | `cite-as` consumers (`report`, `addendum`, `data-software`) |

**Out of scope** (remain theme-local per REQ-0001 / REQ-0006):

- `default`, `home`, `header`, `footer`, nav, hero chrome in `publication.html`
- `_includes/<style>/` skins (`pmlr`, `mlatcl`, `delve`, …)
- Pandoc / `_pandoc`, grant/talk authoring templates

### Survey methodology

#### Phase A — Snapshot inventory (per theme, default branch)

For each consumer repo:

1. List `_layouts/` and `_includes/` matching publication/cite/seo patterns.
2. Record presence/absence of key contract files (see checklist below).
3. `cmp` or content-hash against `lawrennd/jekyll-theme` for shared files.
4. Capture `article.html` wiring (parent layout + includes) — this is the
   path discriminator.

**Key contract checklist**:

```
_layouts/publication.html
_layouts/article.html
_layouts/inproceedings.html
_layouts/techreport.html
_includes/paper_authors_abstract_links.html
_includes/paper_abstract.html
_includes/cite-as.html
_includes/listpaper.html
_includes/listauthors.html
_includes/seo-info.html
_includes/extractinfo_publication.html
_includes/copy_sections.html
_includes/bibtex_copy_section.html (+ apa, ris, endnote)
_includes/paper_google_scholar.html
_includes/paper_open_graph_meta.html
_includes/paper_twitter_meta.html
assets/bib/citeproc.yaml
```

Deliverable: `cip/cip0001/survey-matrix.csv` (theme × file × status:
IDENTICAL / DIFFERS / MISSING / EXTRA).

#### Phase B — Git history (per file family)

For files that differ or define the two paths, use `git log --follow` on
representative themes:

- When was `paper_authors_abstract_links` introduced vs `paper_abstract`?
- When did `publication.html` diverge (uk-ai people sidebar, acceleratescience
  Foundation hero)?
- When were copy_sections / citeproc.yaml added?
- Are mlatcl and lawrennd still byte-identical on the core, or drifting?

Deliverable: `cip/cip0001/history-notes.md` — short narrative per file family,
not a full blame dump.

#### Phase C — Live content spot-check

Pick one content repo per path (e.g. `lawrennd/publications`, `mlresearch/v16`)
and trace which layout names and front-matter keys appear in the wild. Confirms
REQ-0002 layout contracts against real posts.

Deliverable: `cip/cip0001/content-contract-samples.md` — exemplar front matter
fields per layout type.

### Design decisions to make (outputs of this CIP)

1. **Canonical source tree** — likely lawrennd path-1 core, but survey must
   confirm nothing newer exists only on path-2 themes.
2. **Fenner-owned path manifest** — definitive list for install (feeds
   CIP-0002). Prefix: everything in checklist that is identical or should be
   unified; exclude chrome-only diffs in `publication.html`.
3. **Path-2 adapter strategy** — options:
   - **A**: Fenner ships path-1 layouts; type layouts in path-2 themes change
     parent to `publication` (theme-local one-line change).
   - **B**: Fenner ships thin type layouts that delegate to one body include;
     path-2 themes keep `layout: default` via a compatibility layout alias.
   - **C**: Single body include (`paper_body`) used by both paths; deprecate
     duplicate `paper_abstract` / `paper_authors_abstract_links` over time
     behind adapters.

   Recommendation to evaluate in survey: **C with adapters** — satisfies
   REQ-0004 without forcing immediate path-2 chrome changes.

4. **Field normalisation boundary** — `extractinfo_publication.html` as the
   single extract pass (REQ-0003); document legacy aliases accepted at edge.
5. **Chrome split rules** — what stays in theme `publication.html` vs moves to
   optional Fenner hooks (REQ-0001).

### Proposed Fenner repository shape (after survey)

```
jekyll-fenner/
├── _layouts/

│   └── …
├── _includes/

│   ├── seo-info.html
│   ├── copy_sections.html + *_entry + *_copy_section
│   └── …
├── assets/bib/citeproc.yaml      # if survey confirms all consumers need it
└── script/install                # CIP-0002
```

Exact file list is **TBD by survey** — this CIP closes when the manifest is
written and reviewed.

## Implementation Plan

1. **Automate snapshot inventory**
   - Script or documented shell recipe to fetch default-branch file trees from
     all eleven GitHub themes (or use local checkouts where fresh).
   - Produce `survey-matrix.csv`.

2. **Run git history pass**
   - Focus on: `article.html`, `paper_abstract.html`,
     `paper_authors_abstract_links.html`, `publication.html`, `seo-info.html`,
     `extractinfo_publication.html`.
   - Write `history-notes.md`.

3. **Content repo spot-check**
   - Sample posts from path-1 and path-2 content repos; document layout names
     and front-matter keys in `content-contract-samples.md`.

4. **Synthesis workshop**
   - Classify each file: Fenner-owned / theme-local / adapter / deprecated.
   - Choose path-2 unification option (A/B/C).
   - Write `fenner-owned-paths.txt` manifest for CIP-0002.

5. **Update README scope section**
   - Replace provisional lists with survey-backed manifest (after Accept).

## Backward Compatibility

This CIP is design-only. Decisions must preserve REQ-0002:

- No renaming of public layout names without a separate migration CIP.
- Legacy includes (`listpaper`, `cite-as`, `seo-info`) remain callable.
- Path-2 themes must not break on install; adapter choice is explicit.
